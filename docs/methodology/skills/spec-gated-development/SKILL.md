# 스펙 게이트 개발 — 운영 스킬 (Tier 1)

이 스킬은 Tier-0 헌법(`CONSTITUTION.md`)에 종속되며, 충돌 시 헌법이 이긴다. 이 스킬은
헌법을 대체하지 않는다 — 구현 루프(Build) 8단계(`게이트 → 스펙 → 계획 → 격리 → TDD →
리뷰 → 검증 → 통합`, `CONSTITUTION.md` §⑥) 중 **1단계(게이트)** 와 **7단계(검증)**,
그리고 4개 비협상 항목(`CONSTITUTION.md` §⑧) 중 **게이트 순서**와 **검증-전-완료**를
세션 안에서 실제로 걷게 만드는 얇은 체크리스트일 뿐이다. 나머지 6단계(스펙 · 계획 ·
격리 · TDD · 리뷰 · 통합)의 "어떻게"는 Tier 2(기법 팩)나 이 번들의 `templates/`가
채운다 — 이 스킬은 그 단계들을 대신하지 않는다.

## 언제 쓰나

- 새 슬라이스를 시작하려는 순간 → **착수 게이트**.
- "완료됐다 / 통과했다 / 고쳐졌다"라고 말하려는 순간, 커밋하거나 PR을 만들기 직전
  → **완료 게이트**.
- 두 순간 모두: 기억이 아니라 지금 이 세션에서 실제로 문서를 다시 읽었는지, 실제로
  명령을 돌렸는지를 스스로 점검할 때.

## 착수 게이트 (Start Gate)

슬라이스를 시작하기 전, **같은 세션 안에서** 아래 세 개를 전부 표시하기 전에는 다음
단계(스펙 작성)로 넘어가지 않는다.

- [ ] **관련 요구사항 / 수용 기준 재독** — 이 슬라이스가 걸리는 요구사항 ID와 수용
      기준을 SSoT 문서(예: `1-requirements.md`)에서 **기억이 아니라 문서에서** 다시
      읽었다.
- [ ] **경계 확인** — 이 슬라이스가 건드리는 바운디드 영역/모듈 경계를 확인했고,
      다른 영역이 소유한 데이터·개념을 침범하지 않는지 확인했다. 헷갈리기 쉬운
      규칙 쌍이 있으면 `boundary-catalog.md`에서 대조했다.
- [ ] **"참조 문서" 노트 작성** — 무엇을 읽고 무엇을 확인했는지 아래 표로 남긴다
      (빈 칸 없이). 기억에 의존한 인용은 인용이 아니다(C3 · 근거 기반 인용).

| 문서 | 섹션/앵커 | 확인한 내용 |
| --- | --- | --- |
| `<요구사항 문서>` | `<REQ-...>` | `<확인한 내용 한 줄>` |
| `<경계/혼동 카탈로그>` | `<해당 쌍 또는 "없음">` | `<...>` |

더 큰 슬라이스라 상위 단계(전략 · 전술 · 데이터 설계)까지 재독해야 하면
`templates/slice-gate-checklist.md`의 전체 절차를 쓴다 — 위 세 항목은 그 절차의
**항상 실행되는 최소 부분집합**이다.

## 완료 게이트 (Completion Gate)

"완료"라고 말하기 전, 커밋하기 전, 아래를 전부 표시하기 전에는 성공을 주장하지
않는다. **증거 없이는 "완료" 없음.**

- [ ] **무엇이 그 주장을 증명하는지 식별했다** — "테스트 통과", "빌드 성공", "버그
      고쳐짐" 같은 claim마다, 그것을 증명할 실제 명령(테스트 / 빌드 / 린트 / 수동
      확인 등)을 먼저 정했다.
- [ ] **그 명령을 지금 이 세션에서 실행했다** — 이전 실행 결과, "될 것 같다"는
      추정, 부분 실행이 아니라 지금 fresh하게 돌린 전체 실행이다.
- [ ] **출력을 실제로 읽고 확인했다** — exit code와 실패/경고 개수까지 읽었다(로그가
      "괜찮아 보인다"는 인상만으로 넘어가지 않는다).
- [ ] **출력이 주장을 실제로 뒷받침하는지 확인했다** — 아니라면 주장을 낮추고 실제
      상태를 있는 그대로 보고한다.
- [ ] 위 네 가지를 거치기 전에는 "완료" · "통과" · "고쳐짐"이나 만족을 표현하는
      어떤 문구도 쓰지 않았다.

**흔한 회피 패턴(발견하면 되돌아간다)**: "될 것 같다 / 아마"류 추정형 표현으로
검증을 대신하기, 검증 전에 만족부터 표현하기, 부분 검증(예: 린트만)을 전체 검증으로
착각하기, 하위 에이전트 · 도구의 "성공했다" 보고를 재확인 없이 그대로 전달하기.

## 스킬 개념이 없는 도구용 대체 (Fallback)

이 방법론의 규율은 특정 도구 기능이 아니라 **저장소**에 산다(`CONSTITUTION.md` §①).
이 파일을 스킬로 실행할 러너가 없는 도구에서도 아래처럼 같은 두 게이트를 걸을 수
있다.

> 이 파일을 번들 밖으로 복사하면 본문의 `CONSTITUTION.md` 참조를 실제 경로
> (`<repo>/docs/methodology/CONSTITUTION.md`)로 바꾼다(아래 '드롭하기' 참조).

- **스킬 자동 로드가 없다 → 체크리스트를 손으로 들고 다닌다.** 위 두 체크리스트
  (착수 / 완료)를 그대로 복사해 슬라이스 시작 · 완료 시점의 프롬프트에 붙여넣고,
  체크박스를 눈으로 하나씩 확인한다. `00-one-pager.md` ④의 "즉시 실행 체크리스트
  2개"가 이 스킬의 압축판이다 — 스킬 러너가 없으면 그 두 블록만 있어도 된다.
- **슬래시 커맨드 / 매크로는 되지만 스킬 파일 개념이 없다 → 커맨드로 감싼다.** 이
  체크리스트 두 개를 그 도구의 커스텀 커맨드로 등록한다(착수용 하나, 완료용 하나).
  내용은 원문 그대로 옮긴다 — 요약하며 변형하지 않는다(C3).
- **프롬프트 / 규칙 파일을 아예 읽지 않는 도구 → 기계적 훅이 유일한 백스톱이다.**
  이때는 프롬프트 권위 자체가 없으므로, `hooks/`(예: pre-commit)가 게이트 노트 ·
  검증 마커 · 보호 브랜치 직접 커밋 금지를 **커밋 시점에** 강제하는 마지막
  방어선이 된다.
- **세션을 넘는 지속 메모리가 없다 → 이 파일 자체를 저장소 안 메모리로 쓴다.** 매
  세션 첫머리에 이 파일(또는 `00-one-pager.md`)을 수동으로 다시 불러와 컨텍스트에
  올린다.

## Claude Code에 드롭하기

이 파일을 그대로 `.claude/skills/spec-gated-development/SKILL.md`로 복사하면 된다 —
frontmatter의 `name`과 디렉터리명이 일치해야 하므로 내용은 바꾸지 않는다. 다른
도구는 위 "대체" 절을 따른다. 이 파일이 번들 바깥으로 옮겨지면 본문의 `CONSTITUTION.md`
참조는 `entry-points/*.md`와 같은 방식으로 실제 경로(예: `<repo>/docs/methodology/
CONSTITUTION.md` — 경로는 실제 저장소 구조에 맞게 설정한다)로 해석한다. 헌법 원문은
항상 이 스킬과 **별도로 함께** 배치돼 있어야 한다 — 이 스킬은 게이트를 걷게 할 뿐,
헌법 본문을 복제하지 않는다(C1).

## Done when

- 착수 게이트: 세 체크박스를 모두 표시했고 "참조 문서" 노트에 빈 칸이 없다.
- 완료 게이트: 검증 명령을 실행하고 출력을 읽었다는 증거가 실제로 있다 — 그
  전에는 어떤 완료 선언도 하지 않는다.
- 이 스킬의 어떤 문구든 `CONSTITUTION.md`와 어긋나면, **헌법이 이긴다**(§⑧).
