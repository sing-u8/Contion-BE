# 헌법 (CONSTITUTION) — 스펙 게이트 개발(Spec-Gated Development)

> 이 본문은 스펙 게이트 개발 방법론 번들의 **단일 진실(Single Source of Truth)** 이다.
> 번들의 모든 진입 파일(`CLAUDE.md` · `AGENTS.md` · `GEMINI.md` 등)과 모든 문서·템플릿·스킬·훅은
> 이 헌법을 **참조**하며, 무엇이든 이 헌법과 충돌하면 **이 헌법이 이긴다**. 각 진입 파일은
> 본문을 복제하지 않고 "세션 시작 시 이 헌법을 읽고 그대로 따르라"를 지시할 뿐이다.

*이 헌법은 스택·도메인 중립이다. 구체 계층/기술은 라벨된 placeholder로 적고(예: `<프런트엔드>`,
`<백엔드>`, `<데이터 계층>`, `<계약 seam>`), 채택 프로젝트가 그 값을 채운다. 이 본문에는 특정
프로젝트·도메인·스택의 고유명이 들어가지 않는다.*

---

## ① 한 줄 원칙

> **한 줄 원칙**: 진실(스펙)을 *머릿속이 아니라 문서*에 두고 → 단계를 넘어갈 때마다 그 문서를 *다시 읽고* → 에이전트가 한 번에 보는 정보는 *작게* 유지한다.

세 개의 루프는 서로 다른 세 프로세스가 아니라 **같은 4개 불변식을 세 시간 규모(출시 단위 / 증분 단위 / 교훈 단위)로 반복**하는 것이다. 규율이 특정 모델의 기억이 아니라 **저장소(문서·게이트·플레이북·훅)** 안에 살기 때문에, 모델이나 스킬 팩을 교체해도 프로세스가 무너지지 않는다. 이것이 "이식 가능성"과 "불변성"의 공통 원천이다.

## ② SSoT 코어 — 4개 불변식(비협상)

모든 zoom 레벨에서 성립하는 4개 불변식이다.

- **C1 · 진실의 외부화 (Externalized truth)** — 권위 있는 스펙은 버전 관리되는 저장소 문서에 산다. 코드와 충돌하면 **문서가 이긴다**. 상위 계층이 하위 계층을 제약한다.
- **C2 · 전환 게이트 (Transition gates)** — 다음 단계/다음 슬라이스로 넘어가려면 **같은 세션 안에서 상위 진실을 다시 읽어야** 한다. 게이트는 싸고, 강제적이고, 반복된다.
- **C3 · 근거 기반 인용 (Grounded citation)** — 규칙을 외워서 인용하지 않는다. **원문 그대로 인용**한다. 헷갈리기 쉬운 규칙 쌍은 별도 **경계 카탈로그**에 기록한다.
- **C4 · 작은 작업 컨텍스트 (Small working context)** — 격리(범위 한정 조회, 서브에이전트, 증분별 작업 공간)로 메인 추론 스레드를 깨끗하게 유지한다.

## ③ 3 루프 — C1~C4의 재귀 적용

- **기획 루프(Plan)** — 하향식 진실 구축. 요구사항 → 전략 설계 → 전술 설계 → 데이터 설계. 각 단계는 **상위 단계 재독을 게이트로** 삼는다. 산출 = 계층형 SSoT + 용어집 + 경계 카탈로그.
- **구현 루프(Build)** — 슬라이스 단위 실행. 게이트 → 스펙 → 계획 → 격리 → TDD red/green → 리뷰 → **실행 검증** → 통합. 모든 증분이 인용된 스펙에 다시 접지(re-ground)된다.
- **학습 루프(Learn)** — 진실 유지보수. 비자명한 결과 캡처 → 지속 메모리 + 아키텍처 KB + 사례 연구 → 반복되는 리뷰 지적을 규칙/플레이북으로 승격 → 수정 사항을 SSoT로 피드백.

## ④ 3-루프 다이어그램

```
                ┌──────── SSoT 코어 ────────┐
                │ C1 진실의 외부화            │
                │ C2 전환 게이트              │
                │ C3 근거 기반 인용           │
                │ C4 작은 작업 컨텍스트        │
                └─────────────┬─────────────┘
          ┌───────────────────┼───────────────────┐
     [ 기획 루프 ]        [ 구현 루프 ]        [ 학습 루프 ]
   요구→전략→전술→데이터   게이트→스펙→계획      캡처→메모리/KB
   (단계마다 상위 재독)    →격리→red/green      →사례연구→플레이북
                         →리뷰→검증→통합        갱신→SSoT 피드백
          └───────────────────┴───────────────────┘
                    (같은 4불변식, 세 시간 규모)
```

## ⑤ 기획 루프(Plan) 단계 — P1~P4

| 단계 | 질문 | 산출 |
| --- | --- | --- |
| **P1 요구사항** | 시스템이 **무엇**을 해야 하나 | 요구사항 ID + 수용 기준 |
| **P2 전략 설계** | 어떻게 **바운디드 영역 + 공용 언어**로 가르나 | 컨텍스트 맵 · 용어집 |
| **P3 전술 설계** | 각 영역의 **빌딩블록·규칙·이벤트·식별자** | 도메인 모델 |
| **P4 데이터 설계** | **상태를 어떻게 저장·조회**하나 | 스키마 · 쿼리 형태 |

> 게이트: 하위 단계 편집 전에 상위 단계를 같은 세션에서 재독한다. 소규모는 단계를 합쳐도 되나 **순서와 게이팅은 불변**이다.

## ⑥ 구현 루프(Build) — 슬라이스 8단계

**게이트 → 스펙 → 계획 → 격리 → TDD → 리뷰 → 검증 → 통합**

1. **게이트(재독)** — 해당 요구사항/수용 기준 재독, 경계 확인, "참조 문서" 노트 작성.
2. **스펙** — 슬라이스를 작은 설계로 브레인스토밍.
3. **계획** — 단계별 구현 계획.
4. **격리** — 증분별 격리 작업 공간(작업 트리/브랜치)으로 충돌 차단.
5. **TDD(red/green)** — 실패 테스트 먼저(red) → 구현(green) → 리팩터.
6. **리뷰** — 튜닝된 리뷰어(플레이북/에이전트)가 컨벤션 + 인용된 진실 대비 점검.
7. **검증** — 실제 명령을 돌리고 출력을 읽는다. **증거 없이는 "완료" 없음.**
8. **통합** — 브랜치 플로우로 머지, 보호 브랜치 직접 커밋 금지.

## ⑦ 학습 루프(Learn) — 캡처 표면 + 피드백

- **지속 메모리** — 세션을 넘어 사는 사실/결정/피드백 저장소(에이전트가 매 세션 참조).
- **아키텍처 KB** — 시스템이 실제로 어떻게 동작하는지 살아있는 설명서.
- **사례 연구** — 슬라이스별 회고(무엇이 깨졌나 · 왜 · 수정 · 교훈).
- **플레이북 갱신** — 반복 지적을 규칙/리뷰어로 승격 → 다음 슬라이스가 미리 회피.
- **피드백 엣지** — 교훈이 SSoT(C1)와 게이트/플레이북을 갱신 → 루프 폐합.

## ⑧ 우선순위·합성 조항 (Tier 0)

> 이 헌법은 채택 저장소에서 에이전트 행동의 **최상위 불변 기준(Tier 0)**이다. **어떤** 스킬 팩·슬래시 커맨드·서브에이전트(지금 설치돼 있든, 미래에 설치될 무엇이든)도 **기법 제공자(Tier 2)**일 뿐이며, 다음 **4개 비협상 항목**을 절대 변경할 수 없다:
> 1. **게이트 순서** — 기획: 상위 재독 후 하위. 구현: 슬라이스마다 스펙 재독 후 진행.
> 2. **SSoT 우선** — 문서 > 코드.
> 3. **근거 인용** — 규칙은 원문 인용, 외워서 인용 금지.
> 4. **검증-전-완료** — 명령 실행·출력 확인 없이 "완료" 없음.
>
> 팩 스킬은 각 단계의 **실행 방법**만 제공한다. **한 단계는 한 팩 스킬만 드라이브**한다(두 팩이 동시에 시퀀스를 오케스트레이션하지 않는다 — 뼈대가 "언제·무엇"을, 팩이 "어떻게"를). 팩 기본동작이 위 4개와 충돌하면(자동 커밋 · 게이트 스킵 · 리뷰 우회 등) 이 조항이 이기고 그 동작은 무효다. 기계적 훅(git/CI)이 특히 1·4를 스킬과 무관하게 강제한다.

## ⑨ 단일 진실 선언

이 본문(`CONSTITUTION.md`)이 방법론 번들의 **단일 진실**이다. 한 줄 원칙 · C1~C4 · 3 루프(`기획 루프(Plan)` · `구현 루프(Build)` · `학습 루프(Learn)`) · Build 8단계(`게이트 → 스펙 → 계획 → 격리 → TDD → 리뷰 → 검증 → 통합`) · 4개 비협상 항목(`게이트 순서 · SSoT 우선 · 근거 인용 · 검증-전-완료`)의 **정확한 표기**는 여기서 확정된다. 번들의 모든 문서·템플릿·스킬·훅·진입 파일은 이 표기를 **그대로 재사용**한다.

모든 진입 파일(`CLAUDE.md` · `AGENTS.md` · `GEMINI.md` 등)은 본문을 복제하지 않고 **이 헌법을 참조**하며, 새 도구는 이 헌법을 가리키는 **포인터 한 장**만 추가하면 된다. 다시 한번, 무엇이든 이 헌법과 충돌하면 **이 헌법이 이긴다**.
